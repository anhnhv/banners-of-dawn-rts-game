# M7a: Menus and match settings, art clean-up, two new maps

User request (2026-11-08):

- **Main menu, match setup, pause and settings.** Before this, the game opened straight into a match, and the only screen was the result screen with Play again. Keep the settings simple: difficulty, speed, and so on.
- **Placeholder art.** Replace the art that was only temporary.
- **Two more maps.**

This is the screens part of M7 plus pieces of M10 (art) and M11 (maps). Fog of war, and the rest of M7, M10 and M11, stay where they are in PLAN §12.

---

## 1. Decisions

| #   | Topic            | Decision                                                                                                                                                                                                                                                                      |
| --- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Flow             | `/` opens the **Main Menu**. Any match parameter in the URL (`?play`, `?map=`, `?ai=`, `?setup=`, `?pace=`, `?speed=`, `?army=`, `?enemy=`) skips the menu and starts at once, so the dev shortcuts keep working                                                              |
| 2   | Leaving a match  | Restart, Play again and Quit to menu **reload the page** (with the match URL, or `/`). A reload is the only way to be sure no WebGL context, worker or listener from the old match is left behind                                                                             |
| 3   | Difficulty       | The machine player's modes that exist: **Easy** (default) and **Normal**, plus **Idle** (an opponent that does nothing, for practice). The list comes from `src/ai/profiles/`, so a new mode file appears in the menu by itself. A Hard mode is not part of this step         |
| 4   | Pace             | **Presets only**: Relaxed, Standard, Fast, Blitz, in `src/data/pace.json`. No custom sliders yet. The engine takes the chosen preset per match (`GameOptions.rules`). `game.json` keeps the Standard values as the engine default, and a test keeps the two equal             |
| 5   | Game speed       | 1×, 1.5×, 2× (and 0.5× for watching fights). Picked in Match Setup and changed any time in the match with `+` / `-` or in the pause menu. It only scales time, so it does not change the match itself                                                                         |
| 6   | Pause            | `P` pauses and resumes. `Esc` (when there is nothing to cancel) or the menu button opens the **pause menu**, which also pauses                                                                                                                                                |
| 7   | Surrender        | A new `surrender` command. The engine ends the match at once and the other player wins. The result screen says "You surrendered"                                                                                                                                              |
| 8   | Settings         | Few and simple: edge scrolling, scroll speed, shadows, render quality, FPS line, machine player's status line. They apply at once, are saved in `localStorage` (with try/catch; defaults if storage is blocked), and can be opened from the Main Menu and from the pause menu |
| 9   | Last match setup | Remembered in `localStorage`; Match Setup opens with it. "Quick start" on the Main Menu starts it directly                                                                                                                                                                    |
| 10  | Art              | Every entity gets its own HUD icon (until now several reused another one's). The Catapult gets its own voxel model. A **model viewer** page (`/?models`) shows every model and icon for review                                                                                |
| 11  | Maps             | **Twin Rivers** and **Forest Pass**, both 96×96, as described in PLAN §8.3. Both are generated by scripts (like Green Valley), are 180° rotation symmetric, pass the validator and have a ready-made scenario                                                                 |

## 2. Screens and flow

```
Main Menu ─┬─ Play ──────────→ Match Setup ── Start ─→ Loading ─→ Match ⇄ Pause menu
           ├─ Quick start ───────────────────────────↗               │        ├─ Resume
           ├─ Settings                                                │        ├─ Settings
           └─ How to Play                                             │        ├─ Restart        (reload, same setup)
                                                                      │        ├─ Surrender      → Result
                                                                      │        └─ Quit to menu   (reload to /)
                                                                      └─→ Result ─┬─ Play again   (reload, same setup)
                                                                                  └─ Main menu    (reload to /)
```

All menu screens are DOM overlays in the HUD's pixel style (slate panels, brass buttons, Pixelify Sans). They live in `src/ui/screens/`.

### 2.1 Main Menu

- Title "Banners of Dawn" and a one-line tagline.
- Buttons: **Play**, **Quick start** (shows the last setup in one line, for example "Green Valley · Easy · Standard"), **Settings**, **How to Play**.
- Background: the sky color with a soft pixel pattern. A 3D background stays for later.

### 2.2 Match Setup

| Option     | Values                                                                                                  | Default               | Where it acts                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------- | --------------------- | ------------------------------------------------------------- |
| Map        | Every map in `maps/index.json`: name, size, description and a minimap preview                           | the `recommended` map | `bootGame` loads it                                           |
| Opponent   | Easy / Normal (from the AI profiles, with each mode's `persona` as the help text) / Idle                | Easy                  | `WorkerAIController` mode, or no AI                           |
| Start      | **Ready-made battle** (the map's `scenario`) / **Standard start** (Town Hall and the map's start units) | Ready-made battle     | `GameOptions.scenario`. Disabled when the map has no scenario |
| Pace       | Relaxed / Standard / Fast / Blitz, each with its target match length                                    | Standard              | `GameOptions.rules` (engine), HUD times, AI data              |
| Game speed | 0.5× / 1× / 1.5× / 2×                                                                                   | 1×                    | `GameHost.speed`                                              |

Buttons: **Start match** and **Back**.

### 2.3 Loading

One panel, "Loading Green Valley…", shown while the map is decoded and validated and the 3D scene is built.

### 2.4 In the match

- A **menu button** (≡) at the top right, and a **speed pill** next to the resources ("1×", "Paused").
- Keys: `Esc` cancels placement, targeting or the build menu first, and otherwise opens the pause menu. `P` (or Pause) pauses. `+` / `-` (and numpad) change the speed.
- While the pause menu is open, game input is blocked: no hotkeys, no camera keys, no edge scrolling.

### 2.5 Pause menu

Resume · Game speed (0.5× / 1× / 1.5× / 2×) · Settings · How to Play · Restart · Surrender · Quit to menu. Surrender and Quit ask for confirmation first: the button turns into "Really surrender?" and needs a second click.

### 2.6 Result

As before (Victory / Defeat, match time, statistics), plus:

- the reason: "The enemy Town Hall has fallen", "Your Town Hall has fallen", or "You surrendered";
- buttons **Play again** (same setup) and **Main menu**.

### 2.7 How to Play

One text page: the goal, the economy, building, the army, controls. Illustrated pages stay in M10.

## 3. Pace presets (`src/data/pace.json`)

| Preset       | Gather | Build | Train | Starting resources (F / W / G) | Pop cap | Target length |
| ------------ | ------ | ----- | ----- | ------------------------------ | ------- | ------------- |
| Relaxed      | ×0.8   | ×0.8  | ×0.8  | 200 / 200 / 100                | 100     | 20–30 min     |
| **Standard** | ×1.0   | ×1.0  | ×1.0  | 200 / 200 / 100                | 100     | 12–20 min     |
| Fast         | ×1.5   | ×1.5  | ×1.5  | 500 / 500 / 300                | 100     | 8–12 min      |
| Blitz        | ×2.0   | ×2.5  | ×2.0  | 1000 / 1000 / 600              | 125     | 5–8 min       |

These are the numbers of PLAN §2.11 without the research and era columns (there are no eras).

**How it works**

- `src/shared/rules.ts` has the `MatchRules` type (`pace`, `gatherRate`, `buildSpeed`, `trainSpeed`, `startingResources`, `popCap`), the zod schema of `pace.json`, and `rulesForPace(file, id)`.
- `createGame(map, { rules })` stores the rules in `GameState.rules`. The four places that read `game.json → pace / popCap / startingResources` read the rules instead: gathering, construction time, training time, population cap, and the starting stockpile.
- The ready-made scenario still sets its own stockpile for the players it lists (Green Valley: the human player starts with 600 / 600 / 400).
- The machine player gets "derived" data in `staticInfo().data`: the same game data with `game.pace`, `game.popCap` and `game.startingResources` replaced by the match rules. The AI code is unchanged.
- The HUD shows the real times: training and build tooltips, and "time left" on construction sites, are divided by the pace.
- The AI's own timings (for example, its earliest attack) are in seconds and are **not** scaled by pace in this step.

## 6. The two new maps

Both are made by scripts in `tools/maps/` (`npm run maps:generate` writes all three maps). The scripts share `tools/maps/mapgen.ts`: noise, the 180° mirror, object placement, the encoder, the validator run, and a placer for scenario buildings. Only the human player's half is designed, so the maps are fair by construction. Green Valley's output stays the same byte for byte.

### 6.1 Twin Rivers (96×96)

- A river runs along the diagonal between the bases (top-right to bottom-left on the screen): deep water in the middle, shallow edges and sand banks.
- **Three fords** of shallow water: a wide one in the middle (about 9 tiles) and a narrow one near each end (about 3 tiles).
- Each base has 2 gold mines, 8 berry bushes and a wood line behind it. One **extra gold mine** stands on each side near the outer ford, so holding a ford pays.
- Bases: Town Halls at (77, 77) and (16, 16).
- Feel: chokepoints. Towers at the fords are strong.

### 6.2 Forest Pass (96×96)

- A **dense forest belt**, about 14 tiles thick, runs along the diagonal between the bases.
- **Two passes** cut through it, about 5 tiles wide, each a little off the center. **Two long open routes** run around it, along the map edges, at the far ends of the belt.
- Rock outcrops in the forest make the passes clear to see.
- Each base has 2 gold mines, 8 berry bushes and its own wood. A rich gold mine (1200) sits at the mouth of one pass on each side (each pass has one, at opposite ends), so each player has "its" pass.
- Feel: defending the passes, or cutting through the wood to open a new path.

### 6.3 Scenarios

Each new map has a ready-made start like Green Valley's: 4 or 5 Houses, a Barracks, a Stable and a Watch Tower per base, 10 workers gathering, and an army each. The human player's army stands in front of its base. The machine's army waits on its side of the middle of the map, out of its base's tower range. The buildings are placed by the generator on free tiles near the base and mirrored for the machine player, so they always pass the validator.

## 9. Risks

- **The AI on new terrain.** Rivers and a forest belt could trap its placement or its attack paths. Covered by `tests/ai/maps.test.ts`: Normal must win against an idle opponent on each map.
- **Easy must stay beatable.** The novice test runs on each new scenario too.
- **Big forest = many trees.** The trees are instanced, so this is cheap to draw. Not measured on a real GPU yet: the headless browser check uses software rendering (SwiftShader), which is too slow to judge FPS.
- **Pace and the scenario.** The scenario's stockpile replaces the pace's starting resources for the players it lists. This is on purpose: the scenario is a test position.

## 10. Results (2026-11-08)

Everything above is built. `npm run check` is green: 234 tests, about 26 s (40 s before this step).

**Engine fix found by the new maps.** On Forest Pass one simulated minute suddenly took 10–20 s. A CPU profile showed 91% of the time in A*. The machine's workers were sent to trees whose only free neighbour was a pocket enclosed by other trees. Each search ran to its 6000-node cap, failed, and was retried several hundred times a minute, which used up the whole path budget every tick. The fix:

- `Grid.regionAt(x, y)` labels connected land with a flood fill, recomputed lazily after a blocker is added or removed.
- `approachPoint()` only offers free tiles in the unit's own region. `findNode()` already skips nodes without an approach point, so workers now pick a reachable tree.

Green Valley had the same problem on a smaller scale: the test suite went from 25 s to 11 s. A regression test fails without the fix.

**Machine player on the maps** (headless):

| Map          | Novice beats Easy (scenario start, seeds 1–8) | Normal beats Easy (standard start, seeds 1–3) |
| ------------ | --------------------------------------------- | --------------------------------------------- |
| Green Valley | 8 / 8 (14–16 min)                             | 3 / 3 (8–9 min)                               |
| Twin Rivers  | 7 / 8; 1 still running at 20 min              | 3 / 3 (9 min)                                 |
| Forest Pass  | 6 / 8; 2 still running at 20 min              | 3 / 3 (9–10 min)                              |

The novice never lost. Its one attack at 12:00 takes longer to cross the bigger maps.

**Browser check** (headless Chrome over CDP): Main Menu → Match Setup → a match on each map; pause menu; `P`, `+`, `-`; settings changed during a match (shadows off, quality low, FPS on: applied at once and saved); Restart reloads the same setup; Surrender → "You surrendered" → Main menu returns to `/`; the model viewer. No console errors.
