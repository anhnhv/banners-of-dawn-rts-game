# M6.5: Army roster (Barracks: Militia + Archer, new Stable: Scout Rider + Knight)

Status: **implemented 2026-11-07**, waiting for the user's review. The user approved the plan and all four recommendations in §0 on 2026-11-07. What was built and what changed from the plan is in §9.

The unit design (roles, strengths, weaknesses, counters, damage table, stats) is in `docs/units.md`. That file is the one to keep for later; this plan says how it gets into the game and how it is checked.

## 0. The request and the decisions it needs

The request (2026-11-07):

- The Barracks trains Archers as well as Militia.
- A new Stable trains two basic cavalry units.
- For each of the four units:
  1. a clear tactical role;
  2. at least one weakness that can be exploited;
  3. at least one situation where it has the advantage;
  4. no unit is the best choice in every situation.
- A separate doc for the four units' characteristics (`docs/units.md`).

The units already exist in `units.json` with models (Militia, Archer, Scout Rider, Knight), so **no new unit is added**. The work is: who trains them, a Stable building, the balance, a combat bug, the machine player, tests and docs.

Decisions for you (my recommendation first):

## 2. Engine changes (generic, no unit names in code)

### 2.1 Fix: units hit while attack-moving strike back

- **Today:** an idle unit that is hit goes for the attacker (`combat.retaliateSeconds`). A unit on an **attack-move** only scans its own sight. A Militia sees 4 tiles; an Archer shoots from 5. So attack-moving Militia walk past the archers that are killing them.
- **Change** (`systems/targeting.ts`): an attack-moving unit that was hit in the last `combat.retaliateSeconds` attacks that attacker, if it can hit it, before scanning its sight. The chase still ends at `combat.leash`, and then the attack-move continues.
- This applies to every unit and to the machine player alike. No new setting.

### 2.2 Weak against buildings: negative bonus (already allowed)

- `attack.bonus` already accepts negative numbers, and the damage floor `combat.minDamage` (1) still applies.
- `bonus.building: -2` and `bonus.tower: -2` make Archers and Scout Riders do 1 damage to buildings.
- No code change; the `units.json` note explains it.

### 2.3 Not changed

- One armor value, not separate melee and pierce armor.
- No kiting, formations or upgrades.
- Counters come only from class bonuses, HP, armor, range, speed, cost and population.

## 5. The machine player (`src/ai/`)

The AI already builds every army building in `buildMenu` and trains from it, so the Stable works without new code. Three things change, each with a profile setting, so Easy and Normal stay configurable (`docs/ai-modes.md` and its config table are updated; `tests/ai/profiles.test.ts` enforces it).

| New setting                       | Meaning                                                                                                                                                         | Easy              | Normal    |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- | --------- |
| `buildings.militaryBuildingTypes` | How many different kinds of army building it builds, in `buildMenu` order (Barracks first)                                                                      | 1 (Barracks only) | 2         |
| `army.unitChoice`                 | How it picks what to train: `fewest` = the type it has fewest of (today), `random` = any button (seeded), `counter` = the best answer to the enemy army (below) | `random`          | `counter` |
| `army.counterShare`               | With `counter`: the share of new soldiers that follow the counter pick; the rest are `fewest`, so the army stays mixed                                          | —                 | 0.7       |

**Counter pick (generic, from the data).** For each unit type it can train now, score it against the enemy soldiers it sees, each weighted by its cost:

- damage it deals per second to each enemy type (bonus and armor included, as in the engine formula);
- damage it takes per second from each enemy type;
- score = how much enemy value it kills per second × how long it lives, per resource it costs.

It trains the type with the best score. With no enemy army in sight, it uses `fewest`.

**Expected results:**

- Normal facing mostly Archers trains mostly cavalry.
- Facing Knights, it trains mostly Militia.
- Facing Militia, it trains mostly Archers.

**Easy stays easy:**

- The child presses any button (`random`) and never builds a Stable.
- The novice test (`tests/ai/novice.test.ts`: Militia only, one attack at minute 12) must still win.
- If random Archers make Easy too strong against that novice, the fallback is `unitChoice: "fewest"` restricted to the first button (Militia), which keeps today's Easy.

**Not changed:** how the AI decides to attack (raw army strength). A matchup-aware strength for the attack decision is a possible later step.

| Unit        | Situation                                                                                                                                                     |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Militia     | A Knight charge into a Militia block of equal cost loses                                                                                                      |

## 7. Steps

Each step ends with `npm run check` green.

1. **Combat fix (§2.1)** and its test.
2. **Data:**
   - Barracks gets the Archer;
   - the Stable is added to the buildings and the build menu;
   - the unit descriptions are updated;
   - production tests.
3. **Stable model (§4)** and the scenario Stables (§3.5). Browser check with a screenshot of the Stable and of the Barracks panel with two train buttons.
4. **Balance:**
   - add `balance.test.ts`;
   - tune `units.json` until it passes;
   - update `docs/units.md` with the final numbers and the measured results, and add its sync test.
5. **Machine player (§5):**
   - add the three settings, the counter pick and their tests;
   - re-run the Easy evidence (novice vs Easy, 3 seeds) and Normal vs Easy;
   - update `docs/ai-modes.md`.
6. **Wrap-up:**
   - PLAN.md: the status table, §2.4/§2.5 (who trains what) and implementation notes;
   - stop for your review. No commit before you approve.

## 8. Risks

- **Probe fights do not always finish:** when both armies survive and their attack-moves end at opposite sides, they stand still. The balance test sends the survivors at each other again until one side is gone, or compares the value left after a time limit.
- **Food:** without decision 3, food-cost cavalry may still be crowded out by archers in long games. The balance tests are equal-cost fights, so they do not show this. The AI matches would.
- **Easy getting stronger:** Archers beat the novice's all-Militia army. This is covered by the novice test and the fallback in §5.
- **Test time:** `balance.test.ts` runs about 30 short fights, a few seconds in total. The AI matches stay the slowest part of `npm run check`.
